好问题——这确实是命名上最容易让人困惑的地方。核心原因是：**在图神经网络里，"Conv" 已经被泛化成"邻域聚合层"的统称**，而不是指 CNN 里那种滑动窗口卷积。

## 1. 「图卷积」本来就是一个宽泛概念

CNN 里的卷积是固定几何位置上的权重共享窗口。但图没有规则的网格结构，无法定义固定窗口。所以图领域的做法是：把"卷积"重新定义为**从邻居聚合信息**这个操作本身。

数学上看，GCN 和 GAT 的结构完全一样，区别只在**聚合时每个邻居的权重系数怎么来**：

GCN（系数是固定的、由度决定）：

```
h_i' = σ( Σ_{j∈N(i)} (1/√(d_i·d_j)) · W·h_j )
                    ↑ 固定系数
```

GAT（系数是学出来的注意力）：

```
h_i' = σ( Σ_{j∈N(i)} α_ij · W·h_j )
                    ↑ α_ij = softmax_j(LeakyReLU(aᵀ[W·h_i ‖ W·h_j]))
```

看出关键了吗？**GAT 并没有发明新的运算类型，它只是把 GCN 里那个固定的归一化系数替换成了可学习的注意力系数。**所以从 GCN 一路演进到 GAT，层次结构（线性变换 W → 邻居加权求和 → 激活）没变，只是"权重怎么算"变了。既然 GCN 叫 `GCNConv`，把注意力系数插进去的版本自然就延续成 `GATConv`。

## 2. PyG 的接口惯例

在 PyTorch Geometric 里，判断一个层是不是 `Conv`，看的是它的**输入输出约定**，而不是内部算法：

```python
layer(x, edge_index) -> x_new     # 这就是 Conv 的签名
```

所有基于消息传递（`MessagePassing`）的层都遵循这个签名，因此全部以 `Conv` 结尾：

| 类名 | 实际机制 |
|---|---|
| `GCNConv` | 对称归一化的邻居平均 |
| `GATConv` | **注意力加权聚合** |
| `SAGEConv` | 采样 + 拼接/平均 |
| `GINConv` | 求和 + MLP |
| `TransformerConv` | 多头 QKV 注意力 |

注意最后一行——`TransformerConv` 就是纯正的 Transformer 注意力搬到图上，同样叫 Conv。这说明 `Conv` 在这个生态里等价于"图上的一个信息聚合层"。

## 3. 为什么不干脆叫 `GATAttention`

几个现实原因：

- **避免与 `torch.nn.MultiheadAttention` 混淆**。那个是序列/集合上的全局注意力，输入是 `[B, L, D]`；GATConv 的注意力是**受限于图的边**的（只在 `edge_index` 指定的邻居对之间计算），两者语义不同。
- **它确实包含卷积成分**。GATConv 内部有一个共享的线性变换 `W`（对所有节点做 `x @ W`），这部分就是标准的 1×1 卷积／全连接，注意力只是叠在它上面的加权。
- **保持模块可替换**。因为签名一致，你可以直接把网络里的 `GCNConv` 换成 `GATConv` 而不用改 `forward` 里的任何一行——这正是统一命名带来的好处。

## 一句话总结

在图上，`Conv` = 「线性变换 + 邻域加权聚合」。GCN 的权重由度决定，GAT 的权重由注意力决定，**换了系数的算法，没换层的角色**，所以沿用 `Conv` 后缀。
